# 语音功能检查与修复（0.0.7）

## 本次卡顿与无输出的证据

2026-10-13 的 `dist/console.log` 来自旧单文件 0.0.4。该日志记录了 7.3 秒录音、模型 HTTP 200 返回及已生成的回答，同时记录了能量打断触发。旧代码会在停止标志存在时丢弃播报队列，并在回答后同步执行额外记忆请求。

新版关闭能量打断，保留明确停止词和 Esc；文本随着模型返回立即显示。记忆维护在空闲时运行。原 `dist/VoiceAssistant.exe` 更新为启动新版的入口，旧文件保存在 `dist/legacy/VoiceAssistant-0.0.4.exe`。新窗口标题显示版本号，避免继续测试旧程序。

## 实测结果及边界

- 真实本地 Qwen2.5-search 连续三次：均有文字和播报入队。首轮首字 2.89 秒；之后约 0.05 秒。首次播报入队分别约 2.96、0.15、0.11 秒。测试隔离了个人记忆，并拦截系统工具和实际扬声器播放，因此这些数字不等于扬声器首声时间。
- Silero VAD 逐帧识别人声结束，不再按 3/6 秒窗口触发整段解码。人工合成语音叠加持续低频风扇声后，结束判定约 0.45～0.50 秒，识别解码约 0.04～0.08 秒。
- 完整唤醒词“你好黑猫”的六个样例全部触发预期意图；其中“三体”仍被 ASR 听成“身体”，所以不能算全文准确率 100%。完整结果见 `voice_validation.json`。
- 两字唤醒词“黑猫”在同一噪声压力测试中全部漏识别。保留该设置，但建议用完整唤醒词或 F8；没有通过放宽到任意近似词来掩盖漏识别。
- 测试为模型合成、软件叠加噪声，不涵盖不同房间、麦克风距离、其他人讲话等真人场景。

## 功能实现检查

| 功能 | 实现与限制 |
|---|---|
| 单次说话 / F8 | 主窗口内快捷键，不是系统全局快捷键；停止背景监听后仍可单次录音。说完自动结束，Esc 可取消。 |
| 麦克风选择 | 按设备名称与音频接口保存，避免设备编号变化指向错误麦克风。设备断开会说明原因。 |
| 连续对话 | 可选；播报完成后等待下一句，8 秒无语音回到唤醒模式；可说“结束对话”。 |
| 提醒 | 支持中文时长、半小时、混合时长，保存、查看、按编号取消、取消全部。程序必须运行才能到时通知；关闭后会在下次启动处理已到期提醒。 |
| 音量 | 支持数值、增减、查询、静音和取消静音。硬件/COM 失败会返回失败，不再假报成功。 |
| 媒体 | 发送 Windows 媒体键，播放器须支持；播放/暂停为切换，不能验证播放器当前状态。 |
| 窗口 | 控制当前前台窗口；关闭请求不会强制丢弃未保存文档。 |
| 危险操作 | “不要关机”“怎么关闭程序”不会直接变成系统命令。关机等操作仍需窗口确认。 |
| 自由对话 | 依赖 Ollama。自动选模型时优先已加载、较小的对话模型；有等待提示、20 秒无数据超时及空回答报错。 |
| 角色声音 | 已接入 GPT-SoVITS api_v2 配置与试听。没有具体模型/参考素材时不启用、不假称已达到五更琉璃音色；失败时保留文字，避免突然换成通用声音。 |

角色声音的请求字段依据 [GPT-SoVITS 官方 api_v2](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/api_v2.py)，支持自动识别中日混合文本和单独设置参考音频语言。

检索到 [VoiceDub 的 Kuroneko / Gokou Ruri 页面](https://voicedub.ai/create/kuroneko-gokou-ruri-oreimo)，该页标注日语、用户创建的在线声音模型。但没有核实其可下载本地权重、可用集成接口或中文朗读效果，因此没有把它当作已可部署的角色模型。

## 0.0.8 在线声音与角色声音故障

2026-10-13 21:35 的新版日志确认 Edge 服务返回 HTTP 403，程序随后使用 pyttsx3；这不是成功连接了微软在线声音。独立复现默认网络和直连均为 403，显式代理超时。已安装 edge-tts 7.2.8，与当时 PyPI 最新版本及上游 constants 一致。未修改服务鉴权协议或操作系统时钟；403 的上游原因尚未确定，不能宣称微软连接已恢复。

本机 9880、9872、9874 端口均无服务，保存的角色参考音频与台词均为空。前版仅接入 GPT-SoVITS api_v2 客户端，没有部署服务、角色权重和参考素材，因此不能报告角色声音已可用。本次也没有取得并验证五更琉璃模型或参考音频。

修复内容：

- 在线失败原因直接显示在对话中；回退优先本地 VITS，显示实际回退声音，不悄悄变成系统声音。失败请求冷却 60 秒，保存设置会允许重试。
- 设置增加“检测当前声音是否可用”和“保存并试听当前声音”。检测实际合成、不播放、不修改选择、不回退，避免测到其他声音却报告所选引擎成功。
- 角色页单独检查服务的 api_v2 `/tts` 路由、参考文件及实际 WAV 合成。未连接、其他服务、缺失参考文件均明确说明；安装包不包含角色服务和模型。
- Azure 根据资源区域选择公共云、中国云或政府云地址，不再固定中国云。Azure 尚无可用密钥，因此只验证了地址构造和错误处理，没有验证真实订阅合成。
- 播放器启动或状态查询失败会返回错误，增加结束时限，防止空状态循环一直占用播报队列。
- 设置页可滚动，保证较长的角色配置与检测结果仍可访问。

本机实际检测结果见 `voice_connections.json`。本地 VITS 成功生成音频；在线及角色引擎仍报告上述外部条件失败。检测没有播放声音，因此不代表真人已听过扬声器输出或确认音色。

依据：[edge-tts 上游常量](https://github.com/rany2/edge-tts/blob/master/src/edge_tts/constants.py)、[PyPI edge-tts](https://pypi.org/project/edge-tts/)、[微软语音合成 REST 文档](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/rest-text-to-speech)。


## 0.0.9 微软在线语音连接恢复

继续查阅近期上游 Issue 后找到 2026-10-12 的 [PR #491](https://github.com/rany2/edge-tts/pull/491) 和 2026-10-13 的 [PR #492](https://github.com/rany2/edge-tts/pull/492)。7.2.8 虽为已发布最新版，尚未覆盖这次服务变更。前一版停留在“最新版也失败”的判断，排查不够深入。

本项目采用已在本机实测成功的较小改动：把旧合成 WebSocket 地址迁至 `api.msedgeservices.com/tts/cognitiveservices/websocket/v1`，沿用 edge-tts 的音频协议和请求实现；HTTP Date 使用与 Windows 语言无关的标准解析。没有安装未经审查的整个分支，也没有修改系统代理或全局 Python 包。兼容代码只识别已知旧地址；上游未来更换地址时不会覆盖它。未采用 PR #492 的 v2 算法补丁，因此不能把这次验证说成已覆盖所有可能的后续协议变化。

真实连续合成结果：晓晓、晓伊及日语 Nanami 均返回非空 MP3，Windows MCI 可以读取正数时长。首次短句试验约 1.4 秒；随后较长中文与日语样例约 2～4 秒，音频时长约 3～8 秒。均为实际微软音频，没有使用本地回退。数据见 `microsoft_voice_validation.json`；音频样例为 `microsoft-xiaoxiao-test.mp3` 等。未通过扬声器自动播放，用户可自行试听。仍不代表五更琉璃音色已经实现。

0.0.9 保留在线失败时的明确提示、60 秒冷却及本地声音回退。在线服务依赖外部网络和服务端，不能保证未来永不变更。

可对打包程序执行主动检查：`VoiceAssistant.exe --debug --check-voice --no-file`。读取当前选择，实际合成，不播放、不回退、不打印密钥。普通诊断仍仅检查依赖，避免混淆两种结果。
